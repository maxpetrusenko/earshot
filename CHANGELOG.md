# Changelog

## Unreleased

- More agents: `earshot install cursor` (user-level `sessionStart` hook that adds the instruction as `additional_context`, or `--scope project` for a rule file), `earshot install codex --mode instructions` (marked block in `$CODEX_HOME/AGENTS.md`, for when the one `notify` slot is taken or the link must be in the chat) and `earshot install opencode|gemini|droid` (the same block in each agent's global file). New `docs/cursor.md`; `docs/codex.md`, `docs/orca.md` and the README list the agents.
- `tailnet-ip` works when the Tailscale CLI cannot reach the daemon (the macOS system-extension build over ssh): the tailnet IPv4 is read from the network interfaces as a fallback, for both `earshot serve` and the link base URL.
- Player fits its frame: Orca sizes a visual from `documentElement.getBoundingClientRect().height` (plus body overflow), ignores a height of 0 (the frame keeps its 160 px default, which was the blank space under the row, and what iOS got because the page was `display:none`), and never goes below 80 px. The player is now exactly that tall: `html` and `body` have margin 0, padding 0 and no min-height, and the row is centered in an 80 px bar (`ORCA_MIN_FRAME_PX`) instead of sitting at the top of a taller frame. On iOS the page reports 1 px (frame 80 px instead of 160 px, nothing drawn). The cards CSS lost its `min-height:100vh`, which pinned explain frames to the frame height. Tested in Chromium and WebKit with Orca's own base CSS in a viewport much taller than the row.
- `--visual` shows every image: the Explain line is still one line, and its page stacks all the visuals the model made (up to three), one under the other (`src/explain-stack.ts`). The count is unknown when the line prints (the model answers 5 to 10 s later), so a line per visual would leave empty cards whenever it draws fewer, and Orca caps a message at 8 visuals. Each page's CSS is scoped under its own wrapper, since the visual frame's CSP has `frame-src 'none'`. The card page still has each visual on its own page.
- Briefs clean themselves up: new `retention` config (`days: 7`, `max_mb: 1024`) and `earshot prune` (`--dry-run`, `--days`, `--max-mb`). It deletes briefs older than `days`, then the oldest until the folder is under the size cap, and never one that is under an hour old, was served in the last hour (the server marks each brief it serves with `.served`, and re-marks while a stream is open) or has a live worker. `earshot run` prunes at the start, at most once an hour (stamp file `~/.earshot/.prune-stamp`).
- CI: `.github/workflows/ci.yml` on the self-hosted `vps-builder` runner (push and same-repo PRs only): install with a frozen lockfile, lint, typecheck, build, test.
- Director pass required (prompts `visual-explainer.v6` and `visual-explainer-format.v6`, replacing v5): the explain stage asks for five director lines before each visual (`intent`, `key_frame`, `first_look`, `two_second_test`, `motion`) as a `director` object. The gate rejects a visual whose `director` is missing or has an empty line. The lines are logged and saved next to the page as `explain.director.txt` (`explain2`, `explain3`), never rendered or served. The `explainer-visuals` skill now starts with the same pass.
- Perf chart: the cause (201 to 1 queries) is its own strip under the timing chart, in the same image, with a full-width hairline per query and a wide single-query tick. Row headers have a white background, so gridlines no longer cross the labels. Score of the perf image at 390 px: 7 before; 0 on the first Sonnet draft (the new strip was too narrow and the ticks merged into a solid bar, so the two-second test failed); 8 after the second round (Sonnet draft 8, Opus final 8).
- `earshot run --visual` (with `--format auto` in Orca): prints the Explain `::orca-visual` line at once with a placeholder page; the detached worker writes the real image over it, or a deterministic "what changed" card built from the reply's headings and bullets (`src/explain-fallback.ts`) when the result is NO_IMAGE, the gate fails or the LLM call fails. The card is never empty. Without the flag nothing changes: no Explain line. The earshot skill passes `--visual` only for multi-step changes, UI changes, perf results and architecture recommendations.
- Orca player trimmed to one compact row: play or pause, a Listen / Original toggle and elapsed / total time. The seek bar, the 10 second buttons and the speed control are gone. It still collapses on iOS and iPadOS.
- Scoring speed: `scripts/explain-score.ts` scores images in parallel (`--jobs 4`), runs the two-second test and draft rounds on Sonnet and uses Opus only with `--final` (`--draft-model`, `--final-model`, `--twosec-model`, `--width`). `explain-demo.ts` and `explain-preview.ts` render 390 px only for draft rounds and add 1280 px once with `--final`. Seven 390 px images: 127 s before (Opus, one at a time), 28 s after (Sonnet, four at a time). Render and score on pro (`# macbook-only`).
- Explainer round 3 (prompts `visual-explainer.v5` and `visual-explainer-format.v5`): an architecture arrow label is cut at a word boundary (40 characters, no more `observe actio`) and the gate rejects a label that repeats the capability names in the boxes next to it. A range chart headline must carry the reply's own numbers (no digit, no pass). A second measure from the same reply (queries per page 201 to 1) is now a note on each row plus one hairline per query, not a footer line; rows get an optional `note`. The player waveform is clipped to its bracket and dropped when the bracket is under 15% of the axis, so it never runs past the data (`waveSpan`, tested). Axis ticks cap at three steps, row headers hide gridlines, subheads and layer details balance their wrap. Scores at 390 px (Opus, two-second test first): architecture 8, perf 7, perf-illustrative 8.
- Explainer fixes: decimal numbers on a log line are padded to the same places in code (`0.549 needs 0.55` now reads `0.549 needs 0.550`), the log close-up no longer prints caption lines under the two boxes, and one reply makes one perf image (several `range_chart` visuals are merged into the one with the most rows, the others' numbers move to its footer). Thanks to everyone who filed or reviewed the explainer PRs.
- Explainer references pass (prompts `visual-explainer.v4` and `visual-explainer-format.v4`): the stage follows Max's reference images, committed with their input text under `examples/references/`. Phone-first, one concept per image, an eyebrow (PROJECT / KIND), a declarative headline, a one-line subhead and an optional scope footer. New types: `log_compare` (one close-up of two aligned mono lines, only the added precision digits highlighted, computed in code), `state_key` (the same player slot twice, dashed waiting against a green waveform, no axis), `range_chart` (one shared axis from the reply's own numbers, a dot is a value, a bracket is a range, `player: true` draws the track as the player bar with the value printed once where Original becomes available), and `architecture` is allowed again only as layers with real names, an icon on each and one flow direction. Illustrative values must say so in the eyebrow; no axis without numbers; a status line such as "tests pass (343 tests)" stays NO_IMAGE. `explain-score.ts` opens the reference PNGs as the style bar and runs a two-second test first (headline and captions hidden) as a hard gate, then the Opus rubric; `explain-demo.ts --shots` writes the hidden-text `-bare.png` beside each shot. `explain-capture.ts` takes a tight element screenshot of a real page with one outline. New skill `integrations/claude-code/skills/explainer-visuals/` holds the same rules.
- Explainer quality pass (prompts `visual-explainer.v3` and `visual-explainer-format.v3`): sequence and architecture diagrams are rejected at the gate (they show how the code works, not what the user sees), as are "collapses to nothing" and any element labelled "diagram". The prompt asks for before/after mockups and timelines with no invented durations, five to eight drawn elements per panel, and short numberless metric sources. The density gate message now prints three decimals, so 0.549 no longer reads as "0.55, needs 0.55" (the comparison was already `<`, not `<=`); timeline bars and metric cards count more toward density. Fixes: a garbled "measured, , reply states about" metric note, stray marker arrows at 0 colliding with the next lane label, full-width metric cards. `explain-score.ts` adds "Shows how it works" and "Visual clarity"; `explain-demo.ts` honors `EXPLAIN_OUT` and shoots at a short viewport so pages are not padded.
- `--session` now treats an empty value or an unexpanded `${CLAUDE_SESSION_ID}` as no session instead of failing with "--session may contain only letters, digits, - and _". A real but malformed id is still rejected.
- Explainer v2: up to three concepts per reply (`{"visuals":[...]}`), one page each with its own headline (`explain.html`, `explain2.html`, `explain3.html`), each printed as its own Orca line. Prompts `visual-explainer.v2` and `visual-explainer-format.v2`. New `journey` type, per-panel impact captions, outlined changed controls with arrow notes, a shared timeline scale, and a measured-or-target note on every metric with its source. The gate now rejects sparse panels, panels without a caption, placeholder "Diagram" boxes, and anything below 0.55 visual density. Multi-visual runs no longer crash: the bundle allowlist accepts `explain2.html` and `explain3.html`, and a pipeline crash now prints its stack instead of exiting silently.
- `scripts/explain-preview.ts` renders a saved or hand-written answer without an LLM and prints density and gate results; `scripts/explain-score.ts` scores screenshots with Opus and exits 2 when the Claude login cannot be used.
- `examples/`: one reply end to end, with both audio tracks, the edited script, its reasoning, and two explainer pages.
- Claude Code Play button mod (`integrations/claude-code/mod/earshot-player/`): hides the Listen line and draws Play and Original buttons under the reply. Accepts `[Listen](url)`, `[Listen original](url)` and `[Original](url)`, case-insensitive; no-op on the `mobile` surface. `earshot install claude-code --mode mod` copies it to `<claude dir>/skills/earshot-player/` (auto-loaded by Claude Code); `uninstall --mode mod` removes it. The buttons draw only inside Claude Code's own UI, not in Orca or the phone app.
- `--format auto` no longer blocks inside Orca. It used to wait for the finished audio (6.8 s on a short reply, about 19 s on long ones) before printing the player lines. It now writes stand-in pages and prints the `::orca-visual` lines and the links in about 0.4 s; a detached worker makes the audio and rewrites the player page in place when it is ready (the player as soon as both tracks are done, the explain page as soon as its call returns). A failed run leaves a final note instead of a spinner. No Explain line is printed in this mode (it could end up an empty card); for replies of 500 characters or more the worker still makes the explain pages and the card page links them under "What changed". The server now serves `explain.html`, `explain2.html` and `explain3.html` (sandboxed, no script). `--format orca` keeps the blocking behavior. The skill text no longer says the command waits.
- Orca inline player rewritten on the Web Audio API (`decodeAudioData` plus `AudioBufferSourceNode`). The old `<audio src="data:...">` page failed in Orca with `NotSupportedError`. The player page is a compact bar: Play/Pause, Original, a seek bar, back and forward 10 s, speed (1x, 1.25x, 1.5x, 2x), elapsed / total, and Space to toggle.
- `--format auto`: inside Orca (`ORCA_CHAT_SCRATCH_DIR` writable) the skill prints the `::orca-visual` line and then the markdown links; elsewhere it prints the links at once. The Claude Code skill now uses it.
- Orca output is now two independent visuals, player first: `earshot-<id>-player.html` (control bar only, no image) and `earshot-<id>-explain.html` (visual explanation only), then the Listen / Original line last. The player detects iOS and iPadOS at run time and collapses to nothing there, since iOS cannot tap an inline visual. The Mac cannot hide the markdown links (the text is the same on both devices); see docs/orca.md.
- The flow diagram is replaced by an explain stage: one LLM call (prompt `visual-explainer.v1`, verbatim, plus a JSON output-format appendix) turns the reply into a structured spec of what changed (before/after UI, bug before/after, architecture, timeline, sequence or example in/out). Deterministic HTML/SVG templates draw it, so the model never writes markup. It runs in parallel with the script and speech, a quality gate rejects bare label boxes and "Fixed"/"Merged" style labels (one retry, then no image), and small replies get no image. The page shows on iPhone too. `--explain-png` also writes a 1080x1350 PNG; `--no-explain` (or `--no-sketch`) skips it. Metrics are shown as measured only when the model marks them verified, otherwise as a target.
- Prompt `ear-script.v4` (the default short style) no longer asks for a diagram. v3 had lost its body (length, order and voice rules) in the previous release; v4 restores it from v2 and keeps the evidence key. The flow parser, the red/green flow renderer and `scripts/sketch-hitrate.ts` are removed; `scripts/explain-demo.ts` runs the explain stage live over `test/fixtures/explain`.
- Faster first audio when the caller waits for the whole track: the first chunk is sent alone, then the rest. Original first audio on a second Kokoro dropped from about 6.7 s to 0.9 s on a 1 KB reply.
- Removed: `--orca-audio` and the `orca.audio` config key. The stream page needed network access, which Orca pages do not have.

## 1.0.0 (2026-11-11)

First stable release.

- Ear-first rewrite: the memo is written for listening, with the diagram as a glance companion.
- Two links under every reply: `[Listen](...) · [Original](...)`. Both stream while the memo is still being made. The file names `edited.mp3` and `original.mp3` are unchanged, so older links keep working.
- Listen is a short summary (prompt v2, `script.style: short`, the default): 20 to 40 seconds, hard cap of 110 words enforced at a sentence boundary, ordered as what got done, what changed, then one decision as a question. It skips quoted text, file names, paths, number lists and URLs. `story` and `brief` stay selectable.
- Original is the reply read as written, cleaned for speech: code blocks, link targets, URLs, flags, paths and the earshot link line are skipped, and a table becomes one line saying it is in the chat.
- Claude Code skill and Stop hook. The skill asks for a link under every reply; the hook defaults to `min_chars: 80` and `require_tool_use: false`, and skips replies the skill already narrated.
- Codex `notify` program and an MCP server (`narrate`, `brief_status`).
- Scrubbing of keys, tokens and private keys before any network call.
- Tailnet-only serving through `tailscale serve`; there is no public mode.
